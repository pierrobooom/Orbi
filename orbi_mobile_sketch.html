Design rationale

Bubble size

Diameter scales with pressure_score (0–10). Small (≤2): a faint dot you can tap but not really read. Mid (3–6): readable with a one-word label. Large (7+): full label + due date, slight glow. Overdue or score ≥9: pulsing red ring overriding cluster color.

Layout and motion

Force-directed physics, not a grid. Each bubble has a position, a velocity, and three forces acting on it:

  • Cluster spring — soft pull toward the cluster center. Bubbles never escape their cluster.
  • Bubble repulsion — neighbors push back gently so they don't overlap.
  • Brownian wiggle — small random drift so nothing ever goes fully still. Amplitude scales with pressure_score — calm tasks barely move, overdue bubbles wobble visibly (see "Rent" in state 1, animating at ~6s/cycle vs 12–16s for the rest).

Implemented in Skia + Reanimated worklets — a single useFrameCallback updates every bubble's position each frame on the UI thread, so it stays smooth at 60fps even with hundreds of bubbles on Genius.

Navigation — two levels of viewing

Universe view (state 1) scrolls vertically. Each cluster occupies a region of the canvas; additional clusters live below the fold and you scroll down to reach them. At this scale, only the top bubbles per cluster (highest pressure) are rendered — otherwise Genius's hundreds of tasks would be unreadable. The "↓ scroll for more clusters" hint at the bottom of the canvas tells the user there's more universe below.

Cluster dive-in (state 4) — tap a cluster's region in the universe view and you zoom into a focused view of that cluster. Every bubble in the cluster is now rendered and labelled. Same drift physics, just more space per bubble. If the cluster has more bubbles than fit, the dive-in canvas itself scrolls. The back arrow in the header returns to the universe.

Tapping a single bubble (in either view) is the third level — drops into the chat sheet from state 2.

Cross-cluster discovery — links and tags

Bubbles that belong to different clusters but share a topic stay separate objects in different homes — there's no "echo" or "multi-cluster membership." Instead, two mechanisms surface relationships:

  • Links (via RelationshipEdge): specific, bidirectional. The Gym subscription bubble (Finance) and the Gym workout bubble (Health) are connected by an edge. When you open either, the chat sheet shows a "Related" row with chips pointing to the other (see state 2). Tap a chip to jump to that bubble in its home cluster. Same-cluster, cross-cluster, and bubble-to-memory links all use the same chip style.
  • Tags (e.g. gym, subscription, client-X): broader, cross-cutting. Tap a tag chip or use the search bar — every bubble carrying that tag surfaces regardless of cluster.

Auto-suggestion: because all bubble and memory embeddings live in pgvector, the AI can offer links automatically. When you add "gym subscription, £45/mo," the parser sees the existing "Gym workout" bubble nearby in vector space and asks "Link this to your Gym workout?" — no manual tagging required for the common cases.

What lives off-canvas

  • Top header — date, tier pill, today's quota usage. Visible so caps never surprise the user.
  • Bottom mic — single primary action. Hold to speak.
  • Bottom nav — Tasks (list view), Universe (this canvas), Money (finance dashboard). Three tabs total.

Tier differences in the UI

  • Spark — quota strip is hidden by default, surfaces only at ≥80% used as a red warning bar with reset time (see state 1 — that user is at 26/30 = 87%). TTS button on each reply says "Listen (preview)" and is capped to 30s/day. No proactive bubbles popping in unprompted.
  • Pro — quota strip is always visible (no warning behavior needed; 200 turns/day is hard to hit). TTS button is unlimited within 30min/day. Larger 70B model gives noticeably better replies.
  • Genius — quota strip always visible, including the monthly Claude count. Agent occasionally pushes a bubble into view ("Hey, I noticed three meetings this week with no debrief — want to capture them?"). Debrief & weekly review use Claude.

What I deliberately did NOT design here

  • List view of tasks — already a solved pattern, not the differentiator.
  • Onboarding / sign-in flow — Supabase Auth, fairly standard.
  • Finance dashboard — its own screen, will get its own sketch when we get there.
  • Settings, subscription management, profile — standard mobile patterns.

Resolved (this session)

  • More than 4 clusters? Universe view scrolls vertically — more clusters live below.
  • Bubble motion? Yes — constant gentle drift within the cluster, Brownian-style. Overdue bubbles wobble harder.
  • Cluster dive-in shows more bubbles? Yes — state 4. Tapping a cluster zooms in; every bubble in that cluster is rendered and labelled.
  • Cluster identification? Keep the faint orbit outlines. The biggest bubble in each cluster doubles as the cluster identifier — top line is the cluster name (e.g. "Health"), bottom line is the task title (e.g. "Gym · 6pm"). Smaller bubbles in the cluster just show their task title.
  • Catch-all cluster? Named Drift (working name) — neutral gray, no orbit outline, no cluster-name label on its biggest bubble (since "Drift" isn't semantically informative). Bubbles auto-categorize out of Drift as soon as the agent figures out where they belong.
  • Bubbles that span two topics? Stay as separate bubbles in their respective home clusters (Gym workout in Health, Gym subscription in Finance), connected by RelationshipEdge links. The chat sheet on either side shows "Related" chips to jump across (see state 2). Plus tags for broader topic-level slicing.

Also resolved

  • Spark quota strip — hidden until ≥80% used; surfaces as a red warning bar with the midnight UTC reset time. Pro & Genius show it persistently.
  • Bubble tap focus — selected bubble centers; others dim to ~25% opacity (current sketch). Keeps spatial context.
  • Mic interaction — hold OR tap-to-toggle. Hold for quick voice messages (sub-30s), tap to start/stop a long debrief without finger cramp. Same pattern as WhatsApp.
